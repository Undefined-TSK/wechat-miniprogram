# 本机跑起来 · 保姆级说明

> 给「还没有服务器、想先在自己电脑上把判题跑通」的你。
> 全程不花钱，不需要买服务器，不需要装 Docker。

---

## 一句话结论

**你的电脑现在就能判题了。** C/C++ 和 Python 都已经跑通，
一条命令就能验证：

```bash
node judge-service/scripts/local-smoke.mjs
```

看到 `通过 5 项，失败 0 项` 就说明通了。

---

## 一、先理解一件事：判题服务和微信小程序是两回事

很多人会卡在这里，所以先说清楚：

| | 微信小程序 | 判题服务 |
|---|---|---|
| 跑在哪 | 微信的服务器 + 用户手机 | **你自己的一台电脑/服务器** |
| 干什么 | 显示界面、收答案 | 真的去编译、运行用户写的代码 |
| 现在状态 | 已经写完，能在开发者工具里预览 | **就在你本机跑着** |

**为什么判题必须单独一台机器？**
因为判题要「真的运行陌生人写的代码」。这件事很危险——
万一有人提交一段把硬盘删掉的代码呢？所以它必须被关进一个「笼子」里跑，
而这个笼子（叫 Docker 沙箱）在自己的电脑上装起来最方便。

**好消息**：在你自己开发、测试、录题的阶段，**不需要笼子**。
只有你自己在提交代码，出不了事。等真要上线、有第二个人能提交代码了，
再切回笼子模式。这就是下面要讲的两种模式。

---

## 二、两种模式，一句话区别

| 模式 | 怎么开 | 什么时候用 | 安全吗 |
|---|---|---|---|
| **本地不设防模式** | `JUDGE_SANDBOX=local` | 自己开发、录题验证 | ⚠️ 不设防，只有你自己用才安全 |
| **Docker 沙箱模式** | `JUDGE_SANDBOX=docker`（默认） | 上线、有别人提交代码 | ✅ 12 层隔离 |

> **默认是 docker**。这是刻意的——安全的选项才是默认值，
> 想用不设防模式必须你自己明确写出来。

---

## 三、怎么跑起来（三步）

### 第 1 步：确认工具链装好了

判题需要「编译器」才能跑别人的代码。

```bash
gcc --version      # C/C++ 需要
python3 --version  # Python 需要
```

有版本号出来就行。**没有的话也不用管**——
冒烟测试脚本会自己去常见安装位置找（比如用 winget 装的 MinGW）。
找不到会明确告诉你缺什么。

> **如果你刚装完 gcc 却提示「没有」**：
> 关掉终端、重新开一个。装完软件后，旧终端里的 PATH 还没刷新。
> 这个坑很容易让人以为「装了却没装上」，然后反复重装。

### 第 2 步：验证判题链路是通的

```bash
node judge-service/scripts/local-smoke.mjs
```

它会真的编译、运行 5 段代码，覆盖四种典型结论：

```
通过  正确答案 → 应判 AC  →  accepted（通过 3/3 个测试点）
通过  用 int 会溢出 → 应判 WA（考点题）  →  wrong-answer（通过 2/3 个测试点）
通过  语法错误 → 应判 CE  →  compile-error
通过  数组越界崩溃 → 应判 RE  →  runtime-error
通过  Python 正确答案 → 应判 AC  →  accepted（通过 2/2 个测试点）
```

**这 5 项为什么值得看**：
第 2 项是「用 int 存累加和」——小数据能过、大数据溢出。
它被判成 `wrong-answer (2/3)`，意思是**前 2 个测试点过了，第 3 个没过**。
这恰好证明了隐藏测试点起作用了（防「硬编码蒙过」）。

### 第 3 步：真的起服务（可选）

想用小程序连本机判题时再跑：

```bash
cd judge-service
JUDGE_SANDBOX=local npm start
```

Windows 上用 PowerShell：

```powershell
cd judge-service
$env:JUDGE_SANDBOX="local"
npm start
```

启动后会打印一条**醒目告警**，告诉你哪些防护失效了。
这不是吓你，是让你清楚边界在哪。

## 四、本地模式到底「弱」在哪（必须知道）

不设防模式下，这些限制**会失效**：

| 防护 | Docker 模式 | 本地模式 | 后果 |
|---|---|---|---|
| 内存上限 | ✅ 有 | ❌ 没有 | 内存超限（MLE）**判不出来** |
| 进程数上限 | ✅ 有 | ❌ 没有 | fork 炸弹能真的炸掉你的电脑 |
| 网络隔离 | ✅ 禁网 | ❌ 能联网 | 用户代码可以访问外网 |
| 只读文件系统 | ✅ 只读 | ❌ 可写 | 用户代码能改你磁盘上的文件 |

**所以这两条红线必须守住**：

1. **只有你自己用的时候才可以开本地模式。**
2. **只要能有第二个人提交代码，或小程序能连到这台机器——立刻切回 `JUDGE_SANDBOX=docker`。**

> 服务里有一道硬闸门：**生产环境（`NODE_ENV=production`）+ 本地模式 = 直接拒绝启动**。
> 这是故意的，不给「先上线再说」的机会。

## 五、常见问题

**Q: 提示「本机没有 gcc」，但我明明装了？**
关掉终端重开一个。装完软件后旧终端的 PATH 不会自动刷新。

**Q: 判题结果说 TLE（超时），但我代码很快啊？**
先确认不是「程序在等输入」。以前有过一个真 bug：测试点的输入没喂给程序，
程序一直等输入 → 超时 → 被判 TLE，而学生会去优化算法，方向完全错。
现在已修好（输入会喂进去并立刻关闭，让程序拿到「输入结束」）。

**Q: `JUDGE_SANDBOX` 拼错了会怎样？**
会告警并**按 docker 处理**，不会静默跑在不安全模式上。

**Q: 我什么时候必须买服务器？**
等你需要「别人也能用」的时候。
在那之前，本机完全够——包括录题、验证测试点、调判分逻辑。
真要上线时的迁移步骤我会另外给你。

**Q: 想省钱，服务器怎么买？**
先别买。等小程序真的有人用了，再按「最小规格 + 按量付费」起步。
判题是 CPU 密集型，配置够用就行，不用买贵的。

## 六、切到 Docker 模式（等你要上线时再做）

到那时你需要：

1. 装 Docker Desktop（Windows）
2. 构建判题镜像：
   ```bash
   cd judge-service
   npm run sandbox:build
   ```
3. 不设 `JUDGE_SANDBOX`（默认就是 docker），或显式设成 `docker`

镜像构建脚本会**自动校验**环境（非 root、无外联工具、无 pip 等），
不合格直接失败——因为这是唯一「主动执行陌生人代码」的地方，不能含糊。
