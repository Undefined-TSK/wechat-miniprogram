# 「XX闯关」多学科游戏化学习小程序 — 整体方案 v1.0

> 文档版本：v1.0 ｜ 2026-10-03
> 定位：面向大学生的通用闯关式学习平台
> 首批科目：C语言、英语四级、英语六级、高等数学、线性代数
> 技术栈：微信原生 + TypeScript ｜ 混合后端（云开发 + 自建判题/AI 服务）

---

## 0. 已锁定的关键决策

| 决策项 | 结论 | 理由 |
|---|---|---|
| 小程序端技术栈 | **微信原生 + TypeScript** | 性能上限最高、微信能力（Skyline/分包异步化/云开发SDK/后台音频）兼容性最好、审核坑最少 |
| 后端架构 | **混合架构**：业务走微信云开发，判题 + AI 走自建服务 | 云函数无法运行 Docker，编程题判题必须独立沙箱服务；其余业务用云开发可省掉登录态对接与运维成本 |
| 题库来源 | **自建题库 + AI 辅助生产 + 人工审核** | 版权可控、可做知识点打标与难度标定、扩科纯内容工作 |
| 首发范围 | **C语言单科完整闭环**，但题型引擎与题库结构做成数据驱动 | 用最小成本验证留存与付费意愿；引擎数据驱动保证后续扩科零改代码 |

### 📌 我的假设（如与实际不符请指出，会影响架构）

1. 只做微信小程序，不考虑支付宝/抖音/App 多端 → 所以选原生而非 uni-app。
2. 团队规模 2-4 人（1 前端 + 1 后端 + 1 教研/运营），开发周期按 14 周排。
3. 首批不追求 UGC 题目投稿，题目全部来自自建题库。
4. 有一个**已认证的微信小程序主体（企业/个体工商户）**；若无，教育类目基本走不通。
5. 首批不接入微信支付实物交易，会员/虚拟币的 iOS 端问题需在 Phase 0 确认。

### ⚠️ 三条必须提前确认的红线（可能决定项目能否上线）

| 红线 | 为什么是红线 | 处理方式 |
|---|---|---|
| **教育类目资质** | 微信「教育 > 在线教育」类目通常要求《办学许可证》或与持证机构合作。这是**最容易导致项目直接卡死**的一环，且周期不可控 | Phase 0 第一件事：去微信公众平台后台试选类目，看实际要求。备选：与持证机构合作 / 调整产品定位与类目（如走「工具 > 教育工具」类目，需核实） |
| **题库内容版权** | 直接复制教材习题、历年真题、教辅题库属高侵权风险，被投诉即下架 | 自建题目标注来源台账；改编题注明「改编」；AI 生成题必须人工审核入库 |
| **iOS 虚拟商品支付** | 苹果政策禁止 iOS 端用微信支付购买虚拟商品（会员/虚拟币/课程）；违反会被拒审 | iOS 端隐藏支付入口，或做「站内点位」设计。需核实最新政策 |

## 1. 产品结构

### 1.1 内容层级模型

```
科目 Subject（C语言 / 英语四级 / 英语六级 / 高等数学 / 线性代数 / …）
└── 章节 Chapter（如 C语言 → 变量与数据类型）
    └── 知识点 KnowledgePoint（如 → 整型与浮点型、类型转换）
        └── 关卡 Level（如 → 类型转换·入门）
```

**关卡四种形态**

| 形态 | 题目构成 | 星级规则 | 解锁条件 |
|---|---|---|---|
| 普通关 | 单一知识点，5-8 题，单一或少量题型 | 正确率 60%/80%/100% → 1/2/3 星 | 前一关 ≥1 星 |
| Boss 关 | 章节混合题型，10-15 题，限时 | 正确率 + 剩余时间 + 最高 Combo 综合 | 本章累计星数达阈值 |
| 挑战关 | 高难题，含编程题，进排行榜 | 只记分数不记星 | 章节通关后开放 |
| 自适应重练关 | 系统按错题 + 掌握度动态生成 | 不记星，只清错题 | 有错题即开放 |

**星级解锁规则**：章节内关卡线性解锁（前一关 ≥1 星）；章节间按累计星数解锁（如第二章需第一章累计 60% 星数）。每章末尾为 Boss 关。

## 3. 通用题型引擎（本项目最核心的技术资产）

### 3.1 设计原则

题目是**纯数据**，页面不感知题型。一道题的标准结构：

```javascript
{
  _id: "q_xxx",
  subject: "c_lang",
  chapterId: "ch_01",
  kpIds: ["kp_int_float", "kp_type_cast"],   // 可挂多个知识点，用于掌握度计算
  type: "single_choice",                      // 题型标识 → 决定用哪个渲染器/判分器
  difficulty: 2,                              // 1-5，用于自适应与组卷
  payload: { /* 题型私有数据：题干、选项、代码、音频URL、空槽位… */ },
  answer: { /* 标准答案 */ },
  judge: {                                    // 判分策略（数据化配置）
    strategy: "exact",                        // exact | set | normalize | numeric | output | sandbox | ai
    options: { tolerance: 1e-6, ignoreCase: true, trimAll: true, partialCredit: 0 }
  },
  analysis: { text: "...", latex: ["\\int_0^1 x^2 dx"], aigc: false },
  source: { type: "original", note: "自编", license: "self" },  // 版权台账
  stats: { attempts: 0, correctRate: 0, avgCostMs: 0, discrimination: 0 },
  status: "published"                         // draft | reviewing | published | offline
}
```

**新增题型 = 注册一个渲染器 + 注册一个判分器**，不改任何页面代码。这是「后续可扩展其他科目」的技术保障。

### 3.2 判分策略分三层

| 层 | 策略 | 适用 | 实现位置 |
|---|---|---|---|
| L1 确定性 | `exact` / `set`（多选，支持半对半分）/ `normalize`（去空格、忽略大小写、全半角归一、正则、多答案任一）/ `numeric`（数值容差）/ `output`（逐行输出比对，忽略行尾空白） | 单选、多选、填空、判断、程序填空、程序阅读输出 | 客户端 + 云端均可，**要求防作弊的场次放云端** |
| L2 编译判分 | `sandbox`：编译 → 跑测试用例 → 按测试点/subtask 给分 | 基础编程、综合编程、算法实现 | 自建 Docker 判题服务 |
| L3 AI 语义判分 | `ai`：评分维度 + 满分点 → 模型输出结构化评分；**与关键词命中双通道交叉验证**，置信度低转人工 | 名词解释与简答、翻译、作文、证明题、复杂度分析 | AI 网关 |

### 3.3 C语言题型矩阵（10 种，全部 P0/P1 覆盖）

| 编号 | 题型 | 判分策略 | 交互组件 | 优先级 |
|---|---|---|---|---|
| T1 | 单项选择 | exact | 选项卡片（点选即判，含代码块题干） | P0 |
| T2 | 多项选择 | set（支持半对半分） | 选项卡片多选 + 提交按钮 | P0 |
| T3 | 填空 | normalize / numeric | 单行输入框（可多空，支持 LaTeX 题干） | P0 |
| T4 | 判断 | exact（布尔） | 双按钮（对/错） | P0 |
| T5 | 名词解释与简答 | **ai** + 关键词命中 | 多行文本（字数提示 + 答题计时） | P1 |
| T6 | 程序填空 | normalize + 可选编译校验 | 代码填空槽（行内高亮 + 空位输入） | P0 |
| T7 | 程序阅读与输出 | output（逐行归一化比对） | 多行文本 / 终端风格输出框 | P0 |
| T8 | 基础编程 | **sandbox**（测试用例，ACM 模式） | WebView 代码编辑器（C） | P1 |
| T9 | 综合编程 | **sandbox**（多测试点 + subtask 部分给分） | 多文件代码编辑器 | P1 |
| T10 | 算法与复杂度 | 混合：选择/填空 + sandbox + **ai**（复杂度分析） | 组合题容器 | P2 |

### 3.4 其他科目题型配置（数据驱动，无需改引擎）

| 科目 | 题型清单 |
|---|---|
| 英语四级/六级 | 听力选择（音频）、听力填空、词汇单选、选词填空、完形填空、阅读理解、长篇匹配、翻译（AI 批改）、写作（AI 批改） |
| 高等数学 | 单选、多选、填空（LaTeX 输入）、判断、计算题（步骤给分，AI 批改）、证明题（AI 批改） |
| 线性代数 | 单选、多选、填空、判断、矩阵运算题（矩阵输入组件）、计算题、证明题 |

> 矩阵输入、LaTeX 公式输入属于新增渲染器，按 3.1 的注册机制扩展即可，不影响已有题型。

### 3.5 答题状态机（答题引擎页的统一骨架）

```
IDLE → LOADING(取题) → ANSWERING(计时/Combo计数)
  → SUBMITTING(本地即时判分 或 上报云端)
  → FEEDBACK(对/错反馈动效 + 解析)
  → NEXT(下一题) 或 FINISH(无题了 → 结算)
异常分支：NETWORK_ERROR(重试/离线队列) / TIMEOUT / CHEAT_DETECTED(中止并上报)
```

关键约束：
- **setData 只传变化字段**，绝不整包 setData（长题干 + 代码块体积大，整包更新必卡）。
- 计时器、Combo、题目索引放在非渲染数据区，只在需要时同步到视图。
- 作答记录本地先落 storage 队列，联网后批量上报（防丢分纠纷）。

## 4. 玩法系统设计

| 玩法 | 机制 | 设计要点 |
|---|---|---|
| **连胜 Streak** | 每日完成 ≥1 个关卡保连胜；连胜天数给经验加成（1.0x → 1.5x） | 断连用「补签卡」挽回（广告/积分获取），降低流失 |
| **段位 Rank** | 青铜→白银→黄金→铂金→钻石→星耀→王者；按科目 XP 累计；赛季 8 周 | 升段/掉段有明确阈值；段位只升不掉的「保护位」降低挫败 |
| **Combo** | 连续答对递增倍率（×1 → ×1.2 → ×1.5 → ×2），答错归零 | 倍率影响关卡评分与掉落；Boss 关 Combo 计入星级 |
| **1V1 PK** | 同知识点同难度抽题 → 双方同题竞速 5 题 → 先答对得分、答错扣时 | **服务端出题与判分**，前端不持有答案；ELO 匹配；异常时长判定为可疑 |
| **学习搭子** | 1V1 同桌关系；共享每日任务进度；可互相发送提醒 | 提醒走订阅消息；搭子关系有「共同连胜天数」 |
| **组队副本** | 3-5 人 Boss 关；答题正确率转化为对 Boss 的伤害；限时 10 分钟 | 掉落平分 + 贡献榜；缺人时允许 AI 队友补位（防等待流失） |
| **排行榜** | 好友榜 / 科目榜 / 全站榜；日 / 周 / 赛季 | 榜单数值全部服务端计算，客户端只读；避免前端可篡改 |
| **成果卡片** | 结算页 / 周报生成分享图（Canvas 绘制 + 小程序码） | 卡面含：科目、星级、正确率、段位、口号；**分享不设奖励**（合规） |
| **抽卡** | 卡池：宠物皮肤、称号、表情、复活卡、经验卡 | **概率公示页 + 保底（如 30 抽必出稀有）+ 未成年人限额** |
| **电子宠物** | 答题喂养 → 饱食度/心情/经验 → 进化形态 → 被动加成 | 情感陪伴是留存钩子；宠物会「催你学习」（订阅消息文案） |

## 5. AI 能力设计

| 能力 | 触发 | 实现要点 |
|---|---|---|
| 题目解析 | 答题后展开解析 | 先查题库预置 `analysis`；缺失则调 AI 生成 → **人工审核后入库缓存**，避免重复计费 |
| 主观题批改 | 简答/名词解释/翻译/作文提交 | Prompt 固定评分维度 + 满分点；输出 JSON（得分/命中点/缺失点/建议）；与关键词命中交叉验证，偏差过大或置信度低 → 转人工/给「参考分」并明示 |
| 学习计划生成 | 用户设定目标（如「30 天过四级」） | 输入：知识点掌握度 + 剩余天数 + 每日可投入时长 → 输出每日任务序列，写入 user_plan |
| 陪伴式提醒 | 每日定时 + 宠物状态 | 订阅消息模板；文案由 AI 生成但**经内容安全过滤**；用户可关闭 |

**AI 三条纪律**
1. 所有 AI 产出内容必须过 `msgSecCheck` + 模型侧安全过滤。
2. AI 生成或 AI 批改的内容必须有可见标识（「AI 解析」「AI 批改，仅供参考」）。
3. AI 解析必须与题干、答案做一致性校验；明显矛盾直接拦截不入库。

### 7.2 服务端（混合架构）

```
┌─────────────── 微信小程序客户端 ───────────────┐
│  答题引擎 · UI · 本地缓存 · 本地确定性判分      │
└───────┬───────────────────────────┬───────────┘
        │ wx.cloud.callFunction      │ HTTPS（云函数中转，前端不持 token）
        ▼                            ▼
┌──────────────────────┐   ┌──────────────────────────┐
│  微信云开发           │   │  自建服务（腾讯云轻量）    │
│  · 云函数（业务API）  │──▶│  · judge-service 判题沙箱 │
│  · 云数据库（题库/进度│   │  · ai-gateway AI 网关     │
│    /错题/社交/订单）  │   │  · admin-api 题库后台 API │
│  · 云存储（听力音频/  │   └──────┬─────────┬─────────┘
│    题图/分享图）      │          │         │
│  · 云调用（订阅消息/  │   Docker 沙箱   AI 模型 API
│    内容安全/小程序码）│   (C/C++/Python)
└──────────────────────┘
```

**为什么判题必须自建**：云函数运行在共享运行时，无法做容器隔离，执行用户提交的任意代码等于把服务器交出去。编程题判题必须在独立 Docker 容器里跑：禁网、只读根文件系统、限 1s CPU / 256MB 内存 / 禁止 fork 炸弹 / 独立临时目录。

**为什么 AI 走网关**：统一模型路由与降级、Prompt 版本管理、结果缓存（省成本）、内容安全前置、流式转发。

**成本控制**：判题服务按需伸缩（低峰缩到 1 个实例）；AI 结果强缓存；云开发选按量付费；听力音频走云存储 CDN 而非自建带宽。

### 7.3 三个必须提前做 POC 的技术难点

| 难点 | 问题 | 推荐方案 | 备选 |
|---|---|---|---|
| **LaTeX 渲染** | 小程序无 DOM，KaTeX 不能直接跑 | **构建期服务端预渲染为 SVG**，随题目存入题库，客户端只渲染 SVG 字符串。最稳、最快、零运行时开销 | `towxml` / `mp-html` + LaTeX 适配器；或自研 KaTeX → 小程序节点转换 |
| **代码编辑器** | 原生 `textarea` 无语法高亮、缩进体验差 | **WebView 内嵌 CodeMirror 6 / Monaco**，postMessage 通信；提交时把代码回传 | 自研轻量高亮 textarea（体验明显更差，仅作降级） |
| **听力音频** | 需要后台播放、倍速、断点续播 | `wx.createInnerAudioContext` + `innerAudioContext.playbackRate`；`app.json` 声明 `requiredBackgroundModes: ["audio"]`；音频存云存储并走 CDN | 短视频组件不适用 |

### 7.4 核心数据模型

```javascript
// 用户 users
{ _id, openid, unionid, nickname, avatarUrl, grade, major,

// 关卡记录 level_records

// 题目 questions（结构见第 3 节）
// 错题 wrong_questions

// 连胜 user_streak
{ _id, openid, current, max, lastActiveDate, makeupCards }

// 赛季与段位 user_rank
{ _id, openid, subjectId, seasonId, rank: 'bronze'|…|'king', xp, tier }

// PK 对战 pk_matches
{ _id, seasonId, players: [openidA, openidB], questions: [qid…],
  scores, winnerOpenid, startedAt, endedAt, status, cheatFlag }

{ _id, raidId, members: [{openid, damage, correctRate}], bossHp, remainHp, status, rewards }

// 宠物与背包 pets, user_items
{ _id, openid, petId, level, exp, hunger, mood, evolveStage, skinId, skills: [] }

// 抽卡 gacha_pools, gacha_records（含概率表与保底计数）
// 商业化 orders, memberships, point_ledger, invites

```

**索引建议**

| 集合 | 索引 | 场景 |
|---|---|---|
| questions | `{ subject, chapterId, difficulty, status }` | 章节抽题 |
| questions | `{ kpIds: 1, difficulty: 1, status: 1 }` | 知识点抽题 / 自适应 |
| level_records | `{ openid: 1, levelId: 1 }`（唯一） | 关卡成绩查询 |
| wrong_questions | `{ openid: 1, mastered: 1, nextReviewAt: 1 }` | 错题本与复习调度 |

**安全规则示例**（云数据库）

```json
// user_progress：只能读写自己的
{ "read": "auth.openid == doc.openid", "write": "auth.openid == doc.openid" }

// questions：所有人可读已发布题目（但答案字段不下发，见下）
{ "read": "doc.status == 'published'", "write": false }
```

> ⚠️ **答案不下发原则**：客户端取题时，云函数必须剔除 `answer` 与 `judge` 字段（仅保留渲染所需的 payload）。只有普通练习关允许本地判分（下发判分所需的最小信息）；PK、排行榜、模拟考、编程题**一律云端判分**。这是防作弊的第一道墙。

### 7.5 题库后台（Web 端，独立于小程序）

小程序的录题效率极低，题库后台必须做成 **Web 管理端**（Vue3 + Element Plus，或直接基于云开发 Web SDK）。

| 模块 | 功能 |
|---|---|
| 题目管理 | 富文本/结构化编辑器；按题型切换编辑模板；LaTeX 实时预览；代码块高亮 |
| 批量导入 | 支持 Excel / Markdown / JSON → 题目结构；导入后进「待审」 |
| AI 辅助生产 | 输入知识点 → AI 生成题干/选项/答案/解析初稿 → 人工编辑 |
| 知识点打标 | 一题多知识点；知识点树管理；必填校验 |
| 难度标定 | 初始人工标 + 上线后用实际正确率自动校准（正确率 >90% 降难度，<30% 升难度） |
| 审核流 | 草稿 → 待审 → 已发布 → 下线；审核记录留痕 |
| 组卷 | 按科目/知识点/题型/难度配比自动组卷 + 手动微调 |
| 版权台账 | 每题的来源类型（原创/改编/授权）、授权凭证、录入人 |
| 数据看板 | 题量、正确率分布、区分度、用户反馈问题题 |

## 8. UI/UX 设计语言

**基调**：多邻国式的「极简 + 卡通关卡地图」——留白充足、色彩克制、卡片式、深色模式完备、动效只服务于反馈。

| 维度 | 规范 |
|---|---|
| 色彩 | 主色单一（建议品牌绿/蓝，如 `#58CC02` 或 `#3D7EFF`），中性灰阶承载 90% 界面；状态色仅 3 个：正确 `#22C55E`、错误 `#EF4444`、连胜火 `#F97316`。禁止大面积渐变堆叠 |
| 深色模式 | 浅色底 `#F7F8FA` / 深色底 `#121212`；卡片浅色 `#FFFFFF` / 深色 `#1C1C1E`；跟系统 + 手动切换（`wx.onThemeChange`），主题变量统一在 `styles/variables.wxss` |
| 护眼 | 正文对比度 ≥ 4.5:1；避免纯白纯黑大面积；长文本行高 1.6；答题页背景饱和度低于卡片 |
| 布局 | 卡片圆角 `24rpx`，卡片间距 `24-32rpx`，页面左右留白 `32rpx`；阴影极浅或无阴影，靠底色区分层级 |
| 字体 | 系统字体；字号阶梯 `24/28/32/40rpx`；字重只用 400 / 600 两档；不用斜体 |
| 动效 | 只做操作反馈：答对 `200ms` 弹跳 + 音效、答错 `150ms` 抖动、Combo 数字递增缩放、星级逐颗点亮、进度条补间。**禁止**装饰性长动画、自动轮播、无意义的粒子特效 |
| 认知负荷 | **单屏只呈现一个决策**：答题页仅显示当前题；Boss 关才引入倒计时压力；排行榜/商店等复杂页面分步呈现 |
| 反馈节奏 | 答对：即时反馈 + 0.4s 后自动下一题；答错：停留等用户点击「查看解析」；答案类信息不抢跑 |

## 9. 合规与风控清单

| 类别 | 措施 |
|---|---|
| **类目资质** | 教育 > 在线教育（需办学许可或机构合作）。⚠️ **需核实最新政策**，Phase 0 必须先确认 |

| 用户隐私 | `wx.requirePrivacyAuthorize` 隐私弹窗；`requiredPrivateInfos` 声明；最少必要采集；**提供账号注销入口**；隐私政策页 |
| 未成年人保护 | 青少年模式（时长限制 + 消费限制 + 内容过滤）；抽卡限额；不得诱导付费 |
| AI 生成内容 | 全部过 `msgSecCheck`；AI 内容显式标识；低置信度转人工 |
| 抽卡 | **概率公示页**（每个品质的精确概率）+ 保底机制明示 + 抽卡记录可查 |
| 防作弊 | ①答案不下发；②PK/排行/模拟考服务端判分；③异常作答时长检测（如 <0.5s 作答、全对但时长异常）；④提交频率限制；⑤排行榜服务端计算 |
| iOS 虚拟支付 | iOS 端隐藏微信支付入口（会员/虚拟币/课程）；需核实最新政策 |
| 诱导分享 | 分享不给奖励、不作功能前置、不阻断操作；奖励只与「好友实际注册并学习」绑定 |
| 内容安全 | 用户可输入处（简答、反馈、昵称）全部过安全检测；建立举报入口 |
| 支付合规 | 服务端签名（密钥绝不出现在前端）；订单/退款说明；虚拟物品退换规则明示 |
