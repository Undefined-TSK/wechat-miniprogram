### 三条不可动摇的边界

| 边界 | 规则 | 违反后果 |
|---|---|---|
| **判分** | 只有 `services/judge.ts` 能调判分器，组件和页面一律不许判分 | 需服务端判分的场次被前端绕过，防作弊失效 |

| **setData** | 只传变化字段；会话状态挂在页面实例上，不进 `data` | 长题干 + 代码块整包更新必卡 |

## 1. 数据契约

### 1.1 服务端完整题 `FullQuestion`

```ts
{
  id, subject, chapterId, kpIds[], type, difficulty: 1-5,
  payload: { stem, code?, options?, blanks?, placeholder?, instantSubmit?, ... },
  answer: unknown,                      // 判分依据 —— 永不下发
  judge: { strategy, options? },        // 判分策略 —— 永不下发
  analysis: { text, latex?, aigc? },
  source: { type: 'original'|'adapted'|'licensed', note, license, author },  // 版权台账
  status: 'draft'|'reviewing'|'published'|'offline'
}
```

### 1.2 客户端可见题 `ClientQuestion`

```ts
{
  id, subject, chapterId, kpIds[], type, difficulty,
  payload,                              // 渲染所需
  analysis?,                            // 仅练习关下发
  localJudgeKey?: { strategy, key, options? }   // 仅练习关 + L1 策略下发
}
```

### 1.3 判分结果 `JudgeResult`

```ts
{
  correct: boolean,     // 是否完全正确 —— Combo 递增只看这个
  partial: boolean,     // 部分正确 —— 不递增 Combo，UI 显示「部分正确」
  score: number,        // 得分率 0-1 —— 星级与掌握度用这个
  detail: string,       // 给用户看的一句话（含正确答案提示）
  layer: 'local'|'remote',
  strategy: string,
  reveal?: Reveal       // 允许向用户揭示的答案信息，由判分器填充
}
```

`Reveal` 是「谁能看到答案」的唯一出口：判分器知道答案，所以由它决定揭示什么，渲染器只负责展示。这样渲染器不需要（也不允许）去读判分依据。

```ts
Reveal = {
  correctKeys?: string[],    // 选择题正确项
  acceptedText?: string[],   // 填空题可接受答案（取每组首个展示）
  correctText?: string,      // 数值题
  expectedLines?: string[],  // 程序输出题
  scorePoints?: string[]     // AI 判分返回的评分要点
}
```

## 2. 答案不下发原则

### 2.1 三层防护

| 层 | 措施 | 位置 |
|---|---|---|
| 第 1 层 | 只拷贝白名单字段，**绝不**浅拷贝整个对象 | `sanitizeQuestion` |
| 第 2 层 | 断言：`answer` / `judge` / `source` / `status` 任一存在即抛错；再对序列化结果做一次字符串扫描 | `assertNoAnswerLeak` |
| 第 3 层 | 接线自检逐题验证「练习关下发 / 非练习关不下发」 | `tests/wiring.test.mjs` |

生产环境的第 1、2 层必须跑在云函数侧（`cloudfunctions/getLevelQuestions`），客户端这份是同一套规则的本地实现 + 兜底自检。

### 2.2 本地判分的取舍（必须写清，否则会踩坑）

对选择/判断/填空类题型，`localJudgeKey` 在数学上**等价于答案**——没有别的办法，本地判分必须知道答案。

所以规则是：

> **`localJudgeKey` 只在「普通练习关」下发。练习关不计入任何排行榜、不参与 PK、不作为段位依据。**
> Boss 关 / 挑战关 / PK / 模拟考 / 编程题一律不传该字段，走服务端判分。

实现上由 `services/question.ts` 的 `allowLocalJudge(level)` 控制：只有 `mode === 'practice' | 'review'` 才允许。

这不是妥协，是分层：把「低成本即时反馈」和「必须防作弊的竞技场」分开。练习关要的是体验（点选即判、200ms 反馈），竞技场要的是公平。

## 3. 判分器

### 3.1 接口

```ts
type JudgeFn = (
  userAnswer: unknown,
  judgeKey: unknown,               // 即 FullQuestion.answer
  options?: Record<string, unknown> // 即 FullQuestion.judge.options
) => JudgeResult;
```

注册：`registerJudge(strategy, fn)`。注册表对重复注册直接抛错——静默覆盖会让线上判分口径莫名其妙地变。

### 3.2 五个 L1 判分器规格

所有判分器共用 `judges/shared.ts` 的归一化口径，保证「同一个答案在不同题型下不会被判出两个结果」。

**通用 `options`**

| 参数 | 默认 | 说明 |
|---|---|---|
| `ignoreCase` | `true` | 忽略大小写 |
| `trim` | `true` | 去首尾空白 |
| `halfWidth` | `true` | 全角转半角 |
| `collapseSpaces` | `false` | 连续空白压成一个 |
| `stripAllSpace` | `false` | 删除所有空白 |
| `partialCredit` | `false` | **是否允许部分给分。不开则强制二值化** |

**`exact`** — 归一化后完全相等。用于单项选择、判断。
`judgeKey`: `string`（如 `'B'`）

**`set`** — 集合相等。用于多项选择。

| 情况 | 结果 |
|---|---|
| 多选了错误项 | 0 分（不允许蒙） |
| 全部选对 | 1 分 |
| 漏选但无错选 | 开 `partialCredit` 时按 `命中数 / 正确总数`；否则 0 分 |

`judgeKey`: `string[]`（如 `['A','B','D']`）

**`normalize`** — 多答案归一化匹配。用于填空、程序填空、名词解释（关键词版）。
`judgeKey`:
```ts
{ mode: 'single' | 'multi', accepted: string[] | string[][], pattern?: string }
```
- `single`：命中 `accepted` 任一即可
- `multi`：逐空判定，每空命中各自的可接受答案组
- `pattern`：可选正则兜底，与 `accepted` 是「或」关系；配置了非法正则会被静默忽略，不让脏配置炸掉判分

**`numeric`** — 数值容差。用于数值填空、计算结果。
`judgeKey`: `{ value: number, tolerance?: number, mode?: 'abs'|'rel' }`，默认 `tolerance = 1e-6`、`mode = 'abs'`。
输入会自动剥离单位（`'3.14 cm'` 可解析）、千分位与全角空格。

**`output`** — 程序阅读与输出。

| 口径 | 默认 | 说明 |
|---|---|---|
| 行尾空白 | 一律忽略 | 换行符差异、编辑器自动补空格不影响判分 |
| 行首空白 | 保留 | `printf` 的对齐输出是有意义的；`trimStart: true` 可忽略 |
| 末尾空行 | 忽略 | `ignoreTrailingBlank: false` 可保留 |
| `ignoreCase` / `collapseSpaces` | `false` | 输出的大小写与空格间距通常有意义 |

`judgeKey`: `{ expected: string[] }`。部分匹配时 `detail` 会指出「第 N 行不符合预期」或「行数不一致」。

## 4. 渲染器

### 4.1 为什么用 wx:if 链而不是动态组件

小程序**没有** Vue 的 `<component :is>`、也没有 React 的动态标签。生产上有三种做法：

| 做法 | 评价 |
|---|---|
| **wx:if 链分发（本项目选它）** | 未命中的分支不渲染，零额外开销；调试直观；配合分包异步化即可控体积 |
| 自研模板字符串 + `<template is>` | 无法承载组件的生命周期与 setData，复杂交互会很难写 |
| 把 engine 做成纯 WXML 模板库 | 会退化成「字符串拼 UI」，失去组件复用与类型约束 |

所以容器 `index.wxml` 里是：

```html
<single-choice wx:if="{{renderer === 'single-choice'}}" ... />
<multi-choice  wx:elif="{{renderer === 'multi-choice'}}" ... />
<fill-blank    wx:elif="{{renderer === 'fill-blank'}}" ... />
<program-output wx:elif="{{renderer === 'program-output'}}" ... />
```

> ⚠️ **硬约束**：渲染器注册表里的 `type` 必须与组件 tag 同名。改 tag 名不同步改 `type`，题目会静默不渲染（只显示「未注册的题型渲染器」）。`tests/wiring.test.mjs` 会拦住这种错误。

### 4.2 分包异步化

渲染器注册表的 `approxBytes` 是主包体积看板的输入。规则：

> **单个渲染器超过 300KB 时必须填入 `subpackage` 并走分包异步化，不允许塞进主包（主包内控 1.5MB）。**

`app.ts` 启动时会检查 `rendererSizeReport().oversize` 并告警；接线自检里也有一条断言。

### 4.3 渲染器接口约定

统一四件套：`properties` 进、`event change` 出。渲染器**不接触判分逻辑**，只做两件事：收集输入、在 `locked` 后按 `reveal` 展示对错。

| 渲染器 | properties | 输出事件 | 作答形态 |
|---|---|---|---|
| `single-choice` | `options, value, reveal, locked` | `change { value: string }` | `string` |
| `multi-choice` | `options, value, reveal, locked` | `change { value: string[] }` | `string[]` |
| `fill-blank` | `blanks, value, placeholder, locked` | `change { value: string[] }` | `string[]` |
| `program-output` | `value, placeholder, locked` | `change { value: string }` | `string` |

容器额外接收 `question / feedback / locked / isLast`，向上抛出 `submit { answer }` 与 `next {}`。

## 5. 作答形态契约（最容易踩的坑）

```
single-choice   → string        选项 key，如 'B'
multi-choice    → string[]      选项 key 数组，如 ['A','B','D']
fill-blank      → string[]      按空位顺序，如 ['65','int']
program-output  → string        多行文本，如 'sum=9\ncount=3'
```

形态写错的表现是**判 0 分但用户以为答对了**——不会报错，只会静默失败。

两道防线：
1. 形态判定集中在 `engine/answer.ts`：`emptyAnswerFor()` 保证渲染器拿到类型正确的初值，`isSubmittable()` 只做非空判断（不参与正确性判断）。
2. 测试里有一条专门验证「错形态判 0 分且不抛异常」——判分必须 fail closed，宁可判错也不能因为脏输入崩掉整个答题页。

## 6. 答题状态机

```
idle ──▶ loading ──▶ answering ──▶ submitting ──▶ feedback ──▶ answering
                │                                        └──▶ finished（终态）
                └──▶ error ──▶ loading / answering
```

用显式转移表而非散落的 `if`，目的是消掉「已提交还能再提交」这类并发脏状态：`submitting` 状态下不允许再进 `submitting`，非法转移直接抛错。

页面侧再加一道 `busy` 标志：`await judgeAnswer` 期间重复点击提交直接忽略。

## 7. 关卡会话与 setData 纪律

`LevelSession` 持有**非渲染数据**：题目列表、游标、Combo、计时、作答记录。页面的 `data` 里只有 `view()` 返回的最小载荷。

```ts
// view() 返回的字段（全部是原始类型，可直接 setData）
{ index, humanIndex, total, progressPercent, combo, comboMultiplier,
  elapsedMs, answeredCount, correctCount, isLast }
```

两个具体做法：

1. **计时器只更新一个路径**：`this.setData({ 'view.elapsedMs': elapsed, clock })`，不整包更新。
2. **Combo 倍率阶梯**：`0 → ×1`，`2 → ×1.2`，`4 → ×1.5`，`6 → ×2`。答错归零，最高连对单独记录。

星级与经验：

```
scoreRate = Σ(result.score) / 总题数
stars     = scoreRate ≥ 1.0 → 3 星；≥ 0.8 → 2 星；≥ 0.6 → 1 星；否则 0 星
xp        = 正确题数 × 10 + 星级 × 20 + 最高连对 × 2
```

注意星级用的是 **scoreRate（得分率）**而不是正确率——多选题漏选拿到 2/3 分时，应该被星级认可，但不该递增 Combo。

## 8. 新增一个题型（5 步）

以 T8「基础编程」（云端沙箱判分）为例：

```
① 引擎侧注册判分器
   engine/judges/sandbox.ts  → 实现 judgeSandbox(userAnswer, judgeKey, options)
   engine/judges/index.ts    → 加一行 registerJudge('sandbox', judgeSandbox)
   （不需要改 registry.ts，也不需要改任何页面）

② 渲染器组件
   components/question/renderers/code-editor/index.{ts,wxml,wxss,json}
   properties: value / lang / locked   event: change { value: string }

③ 注册渲染器元信息
   engine/bootstrap.ts 的 RENDERERS 数组里加一项：
   { type: 'code-editor', label: '基础编程',
     componentPath: '/components/question/renderers/code-editor/index',
     judgeStrategies: ['sandbox'], approxBytes: 180000, subpackage: 'pkg-tools' }

④ 容器分发链
   components/question/index.json  → usingComponents 加一行
   components/question/index.wxml  → wx:if 链加一个分支

⑤ 题库与取题白名单
   题目 type 填 'code-editor'、judge.strategy 填 'sandbox'
   sandbox 属于服务端策略 → sanitizeQuestion 自动不下发 localJudgeKey，
   无需额外配置
```

跑一遍 `node tests/wiring.test.mjs`，任何一步漏了都会指名报出来。

2. **`typings/index.d.ts`** 是最小化的 wx 类型声明（`any`），因为当前环境离线装不了 `miniprogram-api-typings`。npm 可用后应替换为官方 typings，届时可打开 `strict` 逐项收紧。
3. **`tsconfig.json` 目前 `strict: false`**——先保证跑通，等云开发环境接入后按模块逐步开启 `strictNullChecks`。
4. **`engine/answer.ts` 是新增的契约层**——如果后续发现某题型需要新的形态，改这里并补测试，不要在渲染器里临时转换。
